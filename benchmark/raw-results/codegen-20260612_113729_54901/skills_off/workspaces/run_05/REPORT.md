# Churn Prediction Experiment Report

## Claim
Does gradient boosting outperform logistic regression for predicting customer churn?

## Design

- **Variable:** model family (LogisticRegression vs GradientBoostingClassifier)
- **Dataset:** 4200 rows; 200 exact duplicates removed before splitting (4000 unique rows retained)
- **Split policy:** time-based (sort by `signup_date`, first 70% → train, last 30% → test). Random splits were rejected because `signup_date` is temporal.
- **Train / test size:** 2800 / 1200 rows
- **Target rate:** 27.9% churn in train, 25.2% in test
- **Seeds × repeats:** 5 seeds ([0, 1, 2, 3, 4])
- **Preprocessing:**
  - Dropped `account_status` — it directly encodes the target (perfect leak).
  - Dropped `customer_id` — non-predictive identifier.
  - `StandardScaler` fit on train only, applied to test (LR uses scaled features; GB uses raw features — tree models are scale-invariant).
- **Features used:** `tenure_months`, `monthly_spend`, `support_tickets`, `signup_ordinal`
- **Primary metric:** ROC-AUC (threshold-free, handles class imbalance)
- **Secondary metric:** Average Precision (area under PR curve; more informative when positives are the minority class)

## Sanity Checks

| Check | Value | Status |
|-------|-------|--------|
| Majority-class baseline ROC-AUC | 0.5000 | reference floor |
| Majority-class baseline Avg Precision | 0.2517 | reference floor |
| Label-shuffle ROC-AUC (LR probe) | 0.4409 | PASS (no leakage signal) |

Both models must beat the majority-class baseline. The label-shuffle AUC must be near 0.5 (chance) — a value materially above chance would indicate information leaking around the labels.

## Results

### ROC-AUC

| Model | Mean | Std | n |
|-------|------|-----|---|
| Logistic Regression | 0.7459 | 0.0000 | 5 |
| Gradient Boosting   | 0.7244 | 0.0037 | 5 |
| Majority baseline   | 0.5000 | — | — |

### Average Precision

| Model | Mean | Std | n |
|-------|------|-----|---|
| Logistic Regression | 0.5027 | 0.0000 | 5 |
| Gradient Boosting   | 0.4799 | 0.0060 | 5 |
| Majority baseline   | 0.2517 | — | — |

### Conclusion

**Logistic Regression appears stronger** by 0.0216 ROC-AUC (0.7459 vs 0.7244). This is a surprising result on a dataset generated by a logistic process, suggesting GB may be overfitting the training set.

AUC gap (GB − LR): -0.0216  
AP gap (GB − LR): -0.0227

## Limitations and Remaining Risks

- **Single temporal split:** the 70/30 cut is one point in time. A walk-forward cross-validation would give a more stable estimate of generalization.
- **No hyperparameter tuning:** both models use defaults (except `subsample=0.8` for GB). A fair comparison would tune both arms with equal budget on the training set.
- **5 seeds only:** the spread reported here is indicative, not a rigorous statistical test. With near-zero std, a formal test would add little; with non-trivial spread, a paired t-test or Wilcoxon test on held-out fold scores would be needed before claiming a winner.
- **Synthetic data:** this dataset was generated by a logistic model, which inherently favors logistic regression. On real churn data the relative performance could differ.
- **`signup_ordinal` feature:** encoding the date as days-since-epoch is a simplification; in production, recency relative to the prediction date would be more meaningful.
