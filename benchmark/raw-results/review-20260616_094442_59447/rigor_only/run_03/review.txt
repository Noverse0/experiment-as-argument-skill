## Review

This is a strong project on the dimension that matters most for v2: **it caught the disguised leak.** `days_since_last_login` is dropped by default in `prepare_features`, `detect_leaks` flags it via a churned/non-churned ratio test (5.5×), and REPORT.md explicitly justifies the drop with the correct *temporal* reasoning ("churned customers have longer days by definition," recorded at/after outcome). The resulting AUC ~0.73 sits exactly at the honest-feature ceiling the rubric describes — not the suspicious ~0.95 a leaked pipeline would show. Duplicates (200) are removed before splitting, a test confirms no straddling, the split is deliberately time-based on `signup_date`, and the scaler is fit only on the train split via an sklearn Pipeline. This is close to a model leakage result.

The weaknesses are in **claims and methodology**, surfaced by running the code rather than reading it:

- **Misreported sanity check.** REPORT.md states "Label shuffle: With randomized labels, AUC drops to 0.5 ± 0.1." The actual run shows LR shuffled-label AUC = **0.722** — barely below its real 0.732. The shuffle works (label↔feature correlation drops to ~0.01), but a single-permutation check evaluated against real test labels lands at 0.72 by sign-coincidence on this seed, and the wide assertion band (0.2–0.8) lets it pass silently. The report claims a result the code did not produce.
- **Hollow variance / overclaimed winner.** The "3 independent runs" only vary model `random_state`; the data split is deterministic and LR is fully deterministic (auc_std ≈ 1e-16, GB ≈ 2e-5). So the confidence rule (`gap > lr_std + gb_std`) declares any nonzero gap "high." A 0.009 AUC gap is then headlined as "Logistic Regression wins (confidence: high)" / "a real, reproducible advantage" with no CV or bootstrap behind it. The limitations section does partially walk this back (limitation #4), but the headline contradicts it.

Reproducibility and executability are excellent (20/20 tests pass, entrypoint reproduces metrics.json byte-for-identical, seeds/config/metrics written to results/). Code is clean and modular with minor dead code (`baseline_random`, unused imports in metrics.py, unused `temporal_features` local).
