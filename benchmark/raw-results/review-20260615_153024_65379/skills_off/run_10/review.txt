This is a strong, honest project that caught the disguised leak. Here is my review.

## Summary

This experiment **correctly identified and excluded the disguised target leak**. `days_since_last_login` is never used as a model feature — `prepare_features` (src/dataset.py:48-55) builds a `feature_cols` list of six honest features and explicitly omits it, with a comment labeling it "TARGET LEAKAGE (derived from churned status)." The test suite even asserts `"days_since_last_login" not in feature_cols` (test_experiment.py:32), and REPORT.md explains the reasoning ("post-outcome feature"). The resulting AUC (~0.71–0.73) lands exactly in the honest-features band rather than the suspicious ~0.95 a leaked pipeline would produce.

**Leakage discipline is otherwise solid:**
- Scaler fit on train split only (`fit_scaler=True` for train, applies the fitted scaler to test — dataset.py:86-87).
- 200 exact duplicates dropped *before* the split (dataset.py:16, verified: 4200→4000), preventing train/test straddle.
- `signup_date` handled deliberately: converted to temporal features, and the report explicitly flags that the split is random not time-based, noting this as a caveat.
- Sanity checks (majority baseline = 0.50, train-overfit check, label-shuffle = ~0.49) are genuine, not no-ops.

**Methodology:** Trivial majority baseline present; AUC plus precision/recall/F1 reported (not accuracy alone) appropriately for the ~27% churn imbalance; both models use fixed hyperparameters with no tuning, so the comparison budget is equal; 5 seeds with mean±std.

**Claims:** The report honestly *refutes* its own framed claim — it set out expecting GB to win and reports "no meaningful difference, GB loses" (diff −0.0118, within std ~0.015–0.022). Limitations are thorough and honest. Minor nit: it labels the held-out metric "validation AUC" when it is really single-split test AUC.

**Reproducibility/Executability:** 8/8 tests pass; entrypoint runs in ~3.2s and reproduces the committed metrics; seeds fixed and logged; metrics written to results/. Dependencies pinned and used. (Minor: the summary block in metrics.json nulls out the raw per-seed `values`, but those are preserved under `results_by_seed`.)

**Code quality:** Clean module split, docstrings, no meaningful dead code.
