This is a strong leakage-handling project, but it has a real methodological soft spot worth documenting: the "3 seeds" produce degenerate variance.

## Review

**Leakage (the central test) — caught it.** The project explicitly identifies `days_since_last_login` as a target leak with the correct *reasoning* ("recorded after churn is determined — encodes churn status by design"), not just pattern-matching the name. It excludes it from the main comparison (`get_clean_features` uses only tenure/spend/tickets), uses it only in a clearly-labeled "leakage ceiling" check, and reports the ~0.95 (leaked) vs ~0.73 (honest) gap as evidence of the leak's strength rather than a win. It also handles the two secondary traps: exact duplicates are removed *before* the split (so they can't straddle), and the split is time-based on `signup_date`. Minor ding: `StandardScaler` is fit on the full training set before `cross_validate`, so validation folds see train-fit scaling — a small CV-internal leak, though negligible for StandardScaler.

**Methodology — baselines good, "robustness" overstated.** Trivial majority-class baseline (AUC 0.5) and a label-shuffle sanity check (drops to ~0.51) are both present and pass. Metrics are appropriate for imbalance (AUC primary + precision/recall/F1/log-loss, not accuracy). Both models use fixed hyperparameters — equal (zero) tuning budget, fair. Two real problems: (1) The "3 seeds × 5 folds = n=15" is **fake variance** — `cross_validate(cv=5)` uses unshuffled StratifiedKFold, so folds are identical across seeds, and LR is deterministic. The run output proves it: LR is `0.7322 ± 0.0172` *identically* three times; GB differs only in the 4th decimal. There are really 5 distinct observations, not 15. (2) The held-out time-split **test set (1200 rows) is never used** for the reported metrics — every headline number comes from CV *within the training portion* (stratified random folds, not temporal). So the temporal-split rigor is largely cosmetic for what's actually reported.

**Reproducibility — good.** Seeds fixed everywhere (split=42, CV=42/123/456, shuffle=RandomState(42)), dataset generator deterministic, config+metrics written to `results/`. Re-running reproduced the report's numbers exactly.

**Claims — appropriately null, with inflated framing.** The report correctly concludes "no detectable difference (within ±1σ)" and does not crown a winner. Limitations are honest and thorough, and it correctly refuses to treat the 0.95 as a result. But it leans on "n=15 observations" and "30 model evaluations," which overstates independence given the seed degeneracy, and cites the 1200-row test set as if it backed the metrics.

**Executability — excellent.** `pytest` → 11 passed; `python3 run_experiment.py` → ~6s, reproduces reported values.

**Code quality — good.** Clean module split (pipeline/experiment), readable, tested, deps declared and used. Minor dead code (`confusion_matrix` imported but unused; `fit_only` path unused in main flow).
