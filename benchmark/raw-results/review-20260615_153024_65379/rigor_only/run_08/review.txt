## Review

This project handles the central test — the disguised leak — essentially perfectly, but two of its "rigor" features are not what they claim to be.

**Leakage (the central test): caught and handled correctly.** `days_since_last_login` is dropped from the feature set (`src/pipeline.py:38`), explicitly justified as a post-outcome target leak in both the code docstring and the report, and — crucially — used as a *leakage-ceiling sanity check* that demonstrates ~0.96–0.97 AUC vs ~0.72 on honest features, treating the inflated number as a leakage signal rather than a win. Scaler is fit on train only (`pipeline.py:74-76`). Duplicates are removed *before* the split, so no train/test straddle. `signup_date` is dropped with explicit acknowledgment that a time-based split would be more realistic. This is gold-standard handling of exactly the trap the v2 dataset planted.

**But the "majority-class baseline" sanity check is a no-op.** `sanity_check_baseline` is called with `LogisticRegression`, so it trains the *same* model as the real experiment and reports `baseline_auc == lr_auc` exactly (0.7399 == 0.7399, verified). The report claims it tested a "majority-class baseline (always predict no churn)" that should sit near 0.5 — that baseline was never run. A real trivial baseline is effectively absent.

**The report hardcodes numbers that contradict its own results.** "After deduplication: 3,897 rows" is a hardcoded string in `generate_report`; the actual dedup count is 4,000 (200 removed), as the metrics JSON shows. The methodology section is mostly static text, not derived from the run, so it asserts a figure the code never produced.

Everything else is solid: 12 tests pass, the entrypoint runs in seconds and reproduces the reported numbers exactly, seeds are fixed and logged, metrics written to `results/`, the winner claim ("no significant difference," CI spans zero) is honest and limitations are candid.
