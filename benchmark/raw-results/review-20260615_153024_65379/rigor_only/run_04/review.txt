## Summary

**Leakage (the central test): PASSED — exemplary.** The project identifies `days_since_last_login` as an outcome-derived leak, drops it from the feature set (`get_features_and_target` uses only `tenure_months, monthly_spend, support_tickets`), and explicitly justifies it ("churned customers have longer inactive periods by definition, recorded post-outcome"). It goes further and *demonstrates* the leak: honest AUC 0.725 vs with-leak AUC 0.959 (+0.234), and treats the ~0.95 as a leakage signal justifying exclusion — exactly the gold behavior. Fit-on-train discipline is correct (scaler fit on train split only). Temporal split by `signup_date` is deliberate; duplicate audit runs and confirms 0 rows straddle the boundary.

**The main flaw — fake variance.** The "5 independent runs (different random seeds)" is a no-op. The train/test split is fixed (sorted by date, no shuffle), and only the model `random_state` varies — which has zero effect for LogisticRegression (std = 0.0000) and negligible effect for GB (std = 0.0002). So the reported "non-overlapping confidence intervals" rest on essentially zero variance: it's a deterministic point difference dressed up as a statistical result. The real uncertainty (single 840-row test set) is never quantified. The report does not notice this.

**Minor issues:** label-shuffle test uses an unseeded `np.random.permutation` (shuffled AUC drifted 0.669→0.625 between runs); its `baseline_auc` field is actually accuracy, mislabeled as AUC.
