## Review

**Summary.** This is an unusually rigorous experiment. It is structured explicitly as an argument: a single variable (model family) is varied while features, folds, seed, and tuning budget are held fixed, and the conclusion is hedged to the strength of the evidence. All declared commands run cleanly and fast from a clean state, all 10 tests pass, and a re-run reproduces the numbers exactly.

**Leakage (the planted traps).** All three planted traps are caught and handled correctly:
- `account_status` (the perfect target leak — `closed` iff `churned==1`) is excluded from `FEATURES` (`src/data.py:20,26`), documented, asserted by a test (`test_account_status_is_a_perfect_leak`), and demonstrated via a `leakage_ceiling` audit that re-adds it and confirms AUC→1.0.
- The 200 exact duplicates are dropped **before** any split (`drop_duplicates()` at `src/data.py:56`), verified by `test_duplicates_dropped_before_split` (n_dropped==200, no residual dupes). This prevents train/test straddle.
- `signup_date` is handled deliberately: rows are time-sorted and split with `TimeSeriesSplit` (expanding window), so train always precedes test; the column is used only for ordering, never as a feature.
- The scaler is inside a `Pipeline` and `clone`d per fold (`src/evaluate.py:51`), so it learns train-fold statistics only — no fit-on-full-data leak.

The one nit: signup_date has ties (up to 11 rows share a date), so a fold boundary can place same-date rows on both sides. Since these are distinct customers, it's not a real leak — just a minor temporal-ordering imperfection not mentioned in limitations.

**Methodology.** Trivial baseline present (`DummyClassifier`, baseline_floor sanity check). Metrics are appropriate for the 0.27 positive rate: ROC-AUC primary, PR-AUC and Brier alongside, accuracy deliberately avoided with justification. Equal tuning budget (defaults for both). Four sanity checks (floor, leakage ceiling, label-shuffle, overfit-tiny) gate trust in the comparison.

**Reproducibility.** Seed (42) and generation seed (7) fixed and logged; env (python/sklearn/numpy/git SHA) captured in `results/metrics.json`; a determinism test asserts identical metrics across re-instantiation; re-run reproduced numbers exactly.

**Claims discipline.** The report claims a winner (LogReg edge, mean diff −0.0179 ± 0.0100, all 5 folds negative, p=0.016) but honestly down-weights the p-value as low-power (n=5), and critically admits the synthetic data is a noisy *logistic* function that structurally favors the linear model — so it does not overclaim generality. Nothing in the report is claimed that the code didn't measure.

**Executability & code quality.** Clean modular structure (`data`/`models`/`evaluate`/`sanity`), no dead code, all declared deps used (scipy optional with graceful fallback). Commands work as documented.
