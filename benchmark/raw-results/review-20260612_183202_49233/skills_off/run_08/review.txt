## Review

This is an exceptionally rigorous experiment that engages directly with every planted trap and handles each one deliberately and transparently.

### Leakage prevention — excellent
- **`account_status`** is correctly excluded as a perfect target leak, and — better than just dropping it — a dedicated `leakage_ceiling` sanity check *re-includes* it to demonstrate it drives AUC to 1.0, which is the empirical justification for the exclusion. The docstring even records the agreement counts (3067 active=0, 1133 closed=1).
- **Scaler** lives inside each `Pipeline` and is `clone()`d and refit per fold on training rows only — genuine split-before-transform, verified in code.
- **Duplicates** (200 planted) are removed via `drop_duplicates()` *before* any split, with the rationale that they would otherwise straddle train/test. Confirmed: `n_rows_used = 4000`.
- **Temporal column** handled deliberately: rows sorted by `signup_date` (stable sort) and evaluated with `TimeSeriesSplit`, so training is on earlier signups and test on strictly later ones. `signup_date` is never a feature.
- Tests assert the leak/id/temporal columns are absent from `X`, and that `account_status` ~perfectly determines the target.

### Methodological validity — strong
- Trivial baseline present (`DummyClassifier(most_frequent)` → AUC ~0.5), plus label-shuffle and overfit-tiny-subset checks — all pass.
- Metrics are ROC-AUC + average precision, appropriate for the 27% churn imbalance; accuracy is explicitly rejected.
- Fair single-variable design: same zero tuning budget for both arms, identical preprocessing.
- Minor reservation: declaring an outright "winner" off n=5 *correlated* TimeSeriesSplit folds is slightly aggressive, but the report hedges this heavily and grounds the claim on sign-consistency + small spread rather than the (admittedly approximate) p-value.

### Reproducibility — excellent
Seeds fixed and logged (`random_state=42`, `label_shuffle_seed=0`, dataset `seed=7`). Config, seeds, environment, and full metrics written to `results/metrics.json` + `summary.csv`. I confirmed a re-run produces byte-identical metrics and the dataset regenerates identically.

### Claims discipline — good
Conclusion is backed by 5 folds with reported per-fold values and sd. Limitations section is honest and specific (small/correlated folds, single dataset+seed, no tuning, `signup_date` carries no engineered signal, test scored once). The report makes no claim the code didn't measure (accuracy is mentioned in the planning todo but not asserted in REPORT.md).

### Executability — excellent
`pytest` → 15 passed in ~3s. `run_experiment.py` runs clean in ~3s, well under any timeout, and the documented two-command reproduce flow works from a clean state.

### Code quality — very good
Clean four-module separation, good docstrings, single source of truth for features/seed, all declared deps used. Two trivial dead parameters: `_fold_indices(n, ...)` ignores `n`, and `roc_by_arm` is passed to `_comparison_conclusion` but unused. The `test_no_duplicate_rows_straddle` test is weaker than its name (it only asserts index disjointness, which `TimeSeriesSplit` guarantees) — the comment admits this.
