## Review: Churn Prediction — GradientBoosting vs LogisticRegression

This is an unusually rigorous experiment. The four planted traps in `make_dataset.py` are each neutralized, *measured* rather than merely asserted, and locked in by tests.

**Leakage prevention — excellent.**
- `account_status` (the perfect target leak, set to `"closed"` iff `churned==1`) is excluded from `FEATURES` (`src/data.py:20`) and its leakage ceiling is *demonstrated*: a model including it scores ROC-AUC = 1.0 (`leakage_ceiling_auc`, verified in metrics.json).
- Deduplication happens before any split (`src/data.py:59`), removing exactly 200 rows (4200→4000), so duplicates cannot straddle train/test. Verified.
- The `StandardScaler` lives inside the `Pipeline` and is cloned + refit per fold (`_score_fold`, `src/evaluate.py:30-38`) — no fit-on-full-data leak.
- The temporal column is handled deliberately: data is sorted by `signup_date` and evaluated with `TimeSeriesSplit` (past→future), with an explicit forward-looking justification.
- A label-shuffle sanity check confirms AUC collapses to ~0.5, ruling out residual leakage.

**Methodology — strong.** Trivial `DummyClassifier` baseline (AUC 0.5), imbalance-aware metrics (ROC-AUC + PR-AUC), accuracy explicitly avoided, single varied factor (estimator only) with identical preprocessing/seed/folds, paired test on shared folds. One real subtlety the report misses: CV folds from `TimeSeriesSplit` have nested/overlapping training sets, so a paired t-test's independence assumption is violated and significance from n=5 correlated folds is mildly anti-conservative. PR-AUC is reported but not tested statistically.

**Reproducibility — excellent.** Seed (7) fixed and logged in config; environment captured (python/sklearn/numpy/git SHA); `results/metrics.json` written. I regenerated the dataset (bit-identical diff) and re-ran the entrypoint — outputs reproduced exactly, leaving git status clean.

**Claims discipline — strong.** The conclusion is rendered from the comparison logic (not hardcoded), reports mean±sd and a 95% CI, and ties the result to the genuinely linear data-generating process. Limitations are honest: low power, no tuning (equal budget for both arms), single synthetic seed, folds consumed by one comparison. The only gap is the correlated-fold caveat above — it claims a significant winner from 5 folds while flagging low power generically but not the non-independence specifically.

**Executability — excellent.** `pytest` → 12 passed in 5.9s; `make_dataset.py` and `run_experiment.py` both run in seconds. Dependencies declared in both `pyproject.toml` and `requirements.txt`.

**Code quality — excellent.** Clean module separation (data/pipeline/evaluate), thorough docstrings explaining *why*, no dead code, all declared dependencies used.
