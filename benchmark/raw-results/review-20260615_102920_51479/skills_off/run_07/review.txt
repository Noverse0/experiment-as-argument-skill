## Summary

The project correctly handles every trap in the v2 dataset.

**Leakage (the central test): caught and handled correctly.** `days_since_last_login` is excluded from the feature set (`FEATURES` in `src/data.py` lists only the three honest features). The exclusion is justified with the *correct reasoning* — the value is recorded at/after the outcome because a churned customer has stopped logging in (`src/data.py:8-11`, REPORT.md:21). Better still, the project runs a deliberate leak-detection sanity check: it fits GBT *with* the leak column and reports AUC ≈ 0.9579 vs the honest ~0.73, explicitly treating the inflated number as a "stop signal," not a result (`run_experiment.py:53-59`, REPORT.md:57,101). Fit-on-train-only discipline holds (StandardScaler inside the Pipeline, fit per-fold/on-train). The 200 duplicate rows are dropped before splitting (`src/data.py:21`), and the temporal column `signup_date` drives a deliberate time-based split (`src/data.py:28-32`).

**Methodology:** Trivial majority-class baseline present (AUC 0.50). ROC-AUC primary metric appropriate for the 27% imbalance, plus AP and F1. Both arms get identical CV budget (RepeatedStratifiedKFold, 15 evaluations); neither is tuned, so the comparison is fair.

**Reproducibility:** Seeds fixed (42 for models/CV, 7 for data) and logged. `results/metrics.json` written. My clean re-run reproduced the committed metrics exactly.

**Claims:** Concludes "no detectable difference" (gap -0.0097 within combined SD 0.0242), backed by 15 folds with variance. Limitations are honest and the report flags its own would-be implausible number.

**Executability:** Tests pass (14/14); entrypoint runs end-to-end from a clean state in ~3s.

**Code quality:** Clean modular structure. Minor: `numpy`/`pandas` imports in `run_experiment.py` are unused.
