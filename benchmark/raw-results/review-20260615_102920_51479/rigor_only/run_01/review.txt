## Summary

The experiment is rigorous evidence. It **caught the disguised v2 leak** completely and for the right reason.

**Leakage (the central test):** `days_since_last_login` is dropped in `src/data.py:28` with a justification that reasons about *when the value is known* — "churned customers have, by definition, stopped logging in, so this value is recorded after the outcome is determined." This is exactly the post-outcome reasoning required, not name pattern-matching. The other discipline is also sound:
- Duplicates removed *before* any split (`drop_duplicates`, line 24), explicitly to stop original/duplicate pairs straddling train/test.
- `signup_date` handled deliberately: data sorted by it and evaluated with `TimeSeriesSplit`, with `signup_month` extracted as a seasonality proxy.
- Scaler fitted on train only — `StandardScaler` lives *inside* the LR `Pipeline`, so `cross_validate` fits it per-fold. No leakage.
- A label-shuffle sanity check explicitly exists to catch residual feature leakage (AUC ~0.52–0.53, near chance — confirms no leak remains).

The honest AUC is ~0.73, consistent with the rubric's "honest features" expectation (~0.73), not the ~0.95 a leaked pipeline would show.

**Methodology:** Majority-class baseline (AUC 0.500), overfit-tiny, and label-shuffle all present. Metrics are appropriate for 27% positive rate (ROC-AUC primary, plus F1 and Average Precision — not accuracy). Both models use fixed defaults with no tuning, so the tuning budget is symmetric.

**Reproducibility:** Seeds fixed everywhere (data=7, models=42, sanity=42) and logged to `results/metrics.json`. Re-running reproduced metrics exactly and the regenerated CSV is byte-identical.

**Claims:** Reports "no detectable difference" via a conservative gap-vs-noise-floor rule. Limitations are honest (5 folds is thin, no tuning, single seed, low-signal synthetic data). No claim exceeds what the code measured, and the headline number is plausible — not implausibly high.

**Executability:** `pytest` → 19 passed; `python run_experiment.py` → exit 0, regenerated outputs.

Minor nitpicks only: the `dropped_features` note in metrics.json says "post-outcome leak" tersely (the full reasoning lives in code/REPORT), and the report doesn't show the contrastive ~0.95-with-leak number it cites in limitations — it dropped the feature outright rather than demonstrating the inflated AUC. Neither weakens the evidence.
