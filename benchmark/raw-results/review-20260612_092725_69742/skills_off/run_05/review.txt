## Review

**Inventory & execution.** The project is a clean churn-prediction comparison (LogisticRegression vs GradientBoosting). `python3 -m pytest -q` → 8 passed. `python3 run_experiment.py` runs end-to-end in ~30s and reproduces `results/metrics.json` exactly (LR AUC 0.7332±0.0252, GB AUC 0.7308±0.0250).

**Leakage.**
- ✅ The *critical* leak is caught: `account_status` (literally `"closed" iff churned`) is dropped (`experiment.py:43`), and so is `customer_id`. This is the planted trap that matters most, and it's handled correctly and explained.
- ✅ `StandardScaler` is fit on train only, applied to test (`experiment.py:80-87`), and a test asserts this.
- ⚠️ **Duplicates straddle the split.** 200 exact duplicate rows exist. The code *detects* them (`check_duplicates`) and the report *discloses* the risk — but it never calls `drop_duplicates`. A stratified split does NOT prevent the same row landing in both train and test; the report's claim that stratification "minimizes" this risk is wrong (it has no effect on it). So the reported AUCs carry a real, unremoved optimistic bias. Disclosure earns partial credit; failing to fix it does not.
- ⚠️ **Temporal column not handled deliberately.** `signup_date` is turned into an ordinal `days_since_signup` feature and split randomly. A time-based split was acknowledged as "more principled" but not performed.

**Methodology.** Trivial majority-class baseline present (0.7302). AUC-ROC is the primary metric with F1/accuracy alongside — appropriate for the 27% churn imbalance, not accuracy-alone. Both models use library defaults — equal (zero) tuning budget, fair. 5 seeds give a variance estimate. Weakness: the "no difference" verdict rests on a hard `abs(diff) < 0.02` threshold rather than a paired significance test, and the 5 "independent runs" are really 5 re-splits of one dataset.

**Reproducibility.** Seeds fixed (42–46) and logged in the report; `results/metrics.json` is machine-readable; a determinism unit test exists; rerun reproduced the numbers bit-for-bit. No standalone config file, but params are captured in metrics + report.

**Claims discipline.** Honest and restrained — declares "no detectable difference," declines to crown a winner, and the limitations section is genuinely candid (duplicates, temporal, defaults-only tuning, small N). The label-shuffle sanity check is slightly misframed (shuffle is global, pre-split) but the conclusion drawn from it is reasonable. No claim exceeds what was measured.

**Code quality.** Readable, typed, dataclass-structured. Deductions: unused imports (`json`, `asdict`, `StratifiedKFold` in `experiment.py`; `sys` in `run_experiment.py`); `overfit_train_loss` field actually stores accuracy (misleading name); the `if hasattr(model, 'init'): model.init = 'zero'` block (`experiment.py:112-113`) is hacky and applies only to GBM as a side effect; `run_single_seed`'s `LogisticRegression` omits `max_iter` (relies on default 100, fine only because data is scaled); a cosmetic report bug renders the conclusion as "no detectable difference:.".
