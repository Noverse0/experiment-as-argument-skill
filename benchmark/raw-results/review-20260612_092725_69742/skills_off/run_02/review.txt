## Review

I inventoried the project, ran the test suite (`pytest`: 10 passed in ~1s) and the entrypoint (`python3 run_experiment.py`, which completed in seconds and regenerated `results/`), and audited the leakage traps, methodology, reproducibility, and claims.

### What's strong
The **leakage handling is exemplary** — it neutralizes every planted trap, with documented reasoning:
- `account_status` (the target-derived leak) is dropped in `load_and_clean_data`, with a comment explaining it is "closed" iff churned=1.
- The 200 planted duplicate rows are removed with `drop_duplicates` **before** the split, so they cannot straddle train/test. The run log confirms exactly 200 removed.
- The split is **time-based on `signup_date`** (sort + positional slice), not random, with an explicit rationale — train period ends 2024-09-15, test begins there.
- `StandardScaler` is `fit_transform`-ed on train and only `transform`-ed on test; the date column is dropped from features after the split; `customer_id` dropped.
- A majority-class baseline is computed and printed (test baseline acc 0.748), and metrics go well beyond accuracy (ROC-AUC, precision, recall, F1).

It is **executable and reproducible**: both declared commands work from this state, seeds are logged, metrics+report are written to `results/`, and re-running reproduced the committed numbers exactly.

### The core flaw: a vacuous variance design driving an overstated claim
The experiment runs "3 seeds (42, 123, 456) to estimate variance," but **nothing in the pipeline depends on the seed except model `random_state`**. The dedup, time-based split, and preprocessing are deterministic; `LogisticRegression` (lbfgs) is deterministic; `GradientBoostingClassifier` uses no subsampling, so it too is essentially deterministic. The result: LR's metrics are **byte-identical** across seeds and GB varies only at the 1e-6 level (std ≈ 7.6e-6 / 1.1e-16).

The report then treats this near-zero std as a real confidence interval, reports "Overlapping intervals: False," and concludes **"LogisticRegression outperforms GradientBoosting by 0.0111 ROC-AUC"** as a significant finding. That significance is an artifact: the intervals are non-overlapping only because the design has no source of variance, not because the 0.0111 gap is robust. Three identical runs are not three independent measurements. A real variance estimate would require repeated/shuffled splits or cross-validation — neither is present; the comparison rests on a **single fixed split**. The "Same seeds produce identical results" line in the report celebrates this as reproducibility without recognizing it invalidates the variance claim.

Secondary methodology issue: `class_weight="balanced"` is applied to LR but **not** to GB — asymmetric imbalance handling that confounds the accuracy/F1 comparison (though ROC-AUC, the stated primary metric, is threshold-independent).

### Minor
- Dead imports: `train_test_split` is imported in both `src/experiment.py:7` and `src/utils.py:5` and never used (the code uses a manual time-based split).
- The `scaler` is returned through the pipeline but never reused.
- Limitations section is otherwise honest (tuning, imbalance, sample size, duplicates) but omits the central caveat about the single split / vacuous variance.
