## Review: Churn Prediction Experiment

**What it does well.** This experiment handles the three planted traps deliberately and documents each:
- `account_status` is excluded with an explicit "perfect leak" rationale (`experiment.py:54-65`).
- The 200 planted duplicates are removed *before* the split (`load_and_preprocess` runs `drop_duplicates()` prior to `train_test_split`), so they cannot straddle train/test. Verified live: `4200 → 4000 rows (removed 200)`.
- `StandardScaler` is fit on train only, then applied to test (`experiment.py:97-99`), and GB is correctly run unscaled.

**Methodology is solid for an honest study.** It includes a majority-class baseline (0.7295), a label-shuffle sanity check, and reports ROC-AUC/F1/precision/recall — not accuracy alone — appropriate for the 27% churn imbalance. Both models use library defaults, so the "tuning budget" is trivially equal (and honestly disclosed as untuned).

**Claims are disciplined.** The stated hypothesis is "GB outperforms LR," but the conclusion honestly reports a **null result** (LR 0.7398 vs GB 0.7301, diff 0.0097 < combined uncertainty 0.0107) rather than forcing the hypothesis. Variance over 5 seeds is reported, and limitations are candid.

**Weaknesses.**
- **Temporal handling is partial:** `signup_date` is turned into year/month features but evaluated with a random stratified split — no time-based split. This is acknowledged in limitations (acceptable per the bar, but it's the weakest leakage dimension).
- **Label-shuffle interpretation is a category error:** it compares shuffled-label *ROC-AUC* (0.349, 0.466) against an *accuracy* baseline (0.7295) and flags both "⚠ Check." A shuffled ROC-AUC should sit near 0.5, which both roughly do — the test is fine but the pass/fail logic is wrong-headed. At least it's surfaced rather than hidden.
- **No real significance test:** the diff-vs-combined-std comparison is crude (not a paired test), though conservative and honest.
- **Minor reproducibility gap:** the label-shuffle uses `np.random.permutation` off global state rather than an independent seed; reproducible only because the script runs in fixed order. Re-running reproduced identical shuffle values.
- **Dead imports:** `json`, `Path`, and `StratifiedKFold` are imported in `experiment.py` but unused. `n_duplicates_removed` is hardcoded to 200 rather than computed from the actual dedup count.
