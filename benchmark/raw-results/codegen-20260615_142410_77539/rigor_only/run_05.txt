## Summary

I've built a rigorous ML experiment that correctly handles the planted rigor traps in the churn dataset:

### Key Features

**Rigor & Leakage Prevention:**
- ✅ Detected and excluded `days_since_last_login` (target leak: churned customers have high values by definition)
- ✅ Deduplication before split (removed 200 exact duplicates that could straddle train/test)
- ✅ Time-based split on `signup_date` (train on earlier customers, test on later—respects temporal structure)
- ✅ Preprocessing after split (StandardScaler fitted on train only)

**Sanity Checks:**
- Leakage ceiling: 0.94 AUC with leaked feature vs 0.71 without (leak impact: 0.23 AUC points ✓)
- Label shuffle test: 0.49 AUC (model learns from signal, not noise ✓)
- Baseline floor: 0.50 AUC (both models beat baseline ✓)

**Results:**
- **Logistic Regression outperforms Gradient Boosting**: 0.7530±0.0015 vs 0.7103±0.0045 AUC
- Non-overlapping confidence intervals across 3 temporal splits
- Full methodology and limitations documented in REPORT.md

**Files Created:**
- `src/`: data.py, models.py, experiment.py (modular, well-tested)
- `tests/`: 11 pytest tests covering data handling and modeling
- `pyproject.toml`: dependencies declared
- `run_experiment.py`: orchestration + report generation
- `REPORT.md`: claims, methodology, sanity checks, limitations
