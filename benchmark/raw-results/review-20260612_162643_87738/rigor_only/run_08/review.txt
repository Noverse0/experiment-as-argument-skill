## Review

**Setup.** A churn-prediction experiment comparing `LogisticRegression` vs `GradientBoostingClassifier`, organized into clean modules (`src/data.py`, `pipeline.py`, `evaluate.py`, `checks.py`), with an entrypoint that loads data, splits temporally, runs sanity checks, CV-compares, evaluates once on a held-out set, and writes both `results/metrics.json` and `REPORT.md`. The dataset (`make_dataset.py`) plants three traps: a target-derived `account_status`, 200 exact duplicate rows, and a temporal `signup_date` column.

**Leakage — handled well.** All three traps are caught:
- `account_status` is dropped in `load_and_clean` (`data.py:24`); I confirmed it is uniquely determined by `churned`, so dropping it is correct.
- Deduplication happens *before* the split (`data.py:28`), removing all 200 planted dupes, so they cannot straddle train/test.
- The split is temporal — sort by `signup_date`, last 20% as test (`data.py:31-33`, `temporal_split`).
- `StandardScaler` lives inside the sklearn `Pipeline`, so it is fitted per-fold in CV (via `cross_validate`) and on train-only for the final fit. No fit-on-full-data leakage.
- A label-shuffle check (AUC 0.54, near chance) and an overfit-tiny check (AUC 0.90) provide an independent leakage tripwire.

One minor inconsistency: the final holdout is temporal, but CV uses `StratifiedKFold(shuffle=True)` — random, not time-based. Given the report's own temporal-leakage rationale, a time-aware CV would be more consistent, though this affects only the comparison estimate, not the honest held-out number.

**Methodology — solid with one gap.** Metrics are appropriate for the ~27% imbalance (ROC-AUC, PR-AUC, F1; never accuracy alone). Variance is reported over 5 folds. Both models get the same (zero) tuning budget — defaults only — which is equal-footed and honestly disclosed. The notable gap: **no trivial/majority-class baseline** (e.g. `DummyClassifier`). The label-shuffle test approximates a chance floor but is not the same as a no-skill baseline comparison the rubric asks for.

**Reproducibility — strong.** Seeds are fixed throughout (data `seed=7`, pipelines/CV `random_state=42`, shuffle `999`) and logged in `metrics.json`. Re-running the entrypoint reproduced the committed metrics exactly, and `make_dataset.py` regenerates a byte-identical `churn.csv`.

**Claims — disciplined.** The report concludes "no detectable difference" (gap 0.0105 < pooled CV std ~0.0204) rather than crowning a winner. This is a heuristic, not a formal significance test, but it is conservative and does not overclaim. Limitations are thorough and honest — including the candid note that the simulated logistic DGP structurally favors LR. Nothing is claimed that the code did not measure.

**Executability — clean.** `pytest` → 20 passed; `python run_experiment.py` → ~4s, regenerates both artifacts.

**Code quality — good.** Modular, type-hinted, documented; dependencies all declared and used; no dead code spotted.
