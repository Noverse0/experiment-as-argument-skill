## Summary

A genuinely rigorous experiment that handles all four planted traps deliberately and reaches a conservative, defensible conclusion. The main weakness is in the variance/detectability machinery, not the pipeline hygiene.

## Leakage (strong)
- `account_status` correctly dropped (`src/data.py:25`) and asserted absent in both a sanity check and a unit test. ✓
- Deduplication happens **before** the split (`prepare()` order in `src/data.py:75-79`), so the 200 planted duplicates can't straddle train/test. Verified `n_dupes_removed == 200`. ✓
- `StandardScaler` fitted on train only, transform on test (`build_features`, `src/data.py:64-66`), with a dedicated test. ✓
- Temporal column handled deliberately: chronological split on `signup_date`, with a written rationale and `signup_date` excluded from features. ✓
- Minor smell: the label-shuffle check is a **single permutation** yielding AUC 0.6084, and the pass threshold was loosened from the function default (0.55) to 0.65 to accommodate it (`src/sanity.py:103`). A rigorous shuffle test should average over several permutations rather than tune the threshold to one noisy draw. Not actual leakage (features are i.i.d. of the target), but it weakens the check.

## Methodology (the soft spot)
- Trivial baseline present (`DummyClassifier`), and metrics are imbalance-appropriate (ROC-AUC primary, AP, F1 — not accuracy). ✓ Equal tuning budget (zero, for both) is fair and disclosed. ✓
- **"5 seeds" is largely illusory.** The split is fixed and LogisticRegression/Dummy are deterministic, so only GBM has any seed-to-seed variance (LR std = 0.0000 across all 5 seeds). The seeds repeat the same LR fit five times.
- **Asymmetric detectability bug** (`run_experiment.py:122`): `detectable = gap > max(lr_std, gb_std)` with `gap = gb_auc - lr_auc`. Because `gap` is signed, the "LR wins" branch (`elif detectable and lr_auc > gb_auc`) can never fire — a negative gap always yields `detectable=False`. Here LR actually leads by 0.0146 (≈6× GBM's std), yet the code reports "no detectable difference." The conclusion happens to be scientifically defensible (a single test set gives no real uncertainty estimate for the deterministic LR), but it's reached by a flawed mechanism, not by sound reasoning. Seed-variance ≠ sampling uncertainty; a bootstrap/paired test on the test set is what's needed (and is correctly named in the limitations).

## Reproducibility (strong)
Seeds fixed and logged; config + metrics + sanity results written to `results/metrics.json`; re-running the entrypoint reproduced the file exactly. Dataset generation is deterministic (`make_dataset.py`, seed 7).

## Claims discipline (strong)
The report does **not** declare a winner, matches the displayed numbers, and the Limitations section is honest and thorough (single split, few seeds, no tuning, dropped temporal feature, generalization-to-newer-cohorts caveat). Slight over-framing in presenting "5 seeds" as variance estimation when LR variance is structurally zero, but the 0.0000 std is shown plainly.

## Executability / code quality (strong)
`pytest`: 23 passed in ~3s. Entrypoint runs end-to-end. Dependencies all declared and used. Clean modular layout (`data`/`models`/`evaluate`/`sanity`), good docstrings. Minor: `train_df`/`test_df` returned by `prepare()` are unused downstream; `combined_spread` only surfaces in one conclusion branch.
