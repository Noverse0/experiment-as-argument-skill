## Review

This is a strong, deliberately rigorous submission. All three planted traps were caught and handled correctly.

**Leakage prevention — excellent.**
- `account_status` is explicitly identified as label leakage ("closed" iff `churned==1`) and dropped (`src/data.py:6,25`), with the reasoning documented in REPORT.md.
- The 200 exact-duplicate rows are removed **before any split** via `drop_duplicates(subset=["customer_id"])` (`src/data.py:19`). Verified: dataset is 4200 rows / 4000 unique ids / 200 full dups → cleaned to 4000. Duplicates cannot straddle the split.
- `StandardScaler` is fit on each training fold and only `.transform`-ed on the test fold (`src/evaluate.py:25-27`) — no test statistics leak.
- The temporal column (`signup_date`) is handled deliberately: dropped with an explicit justification (tenure_months captures time-in-service; raw dates without a fixed reference would invite leakage). A time-based split is a defensible alternative, but the choice is reasoned, not ignored.

**Methodology — good.** ROC-AUC is the primary metric with F1 and Average Precision as secondaries — appropriate for the 27% churn imbalance, not accuracy alone. Both models get an identical (zero) tuning budget, a fair comparison. The main gap: there's a "baseline floor" sanity check (model AUC > 0.52) but no trivial baseline classifier (e.g. DummyClassifier) sitting in the comparison table itself. The floor check partially covers this.

**Reproducibility — strong.** CV seeds (0,1,2) and model/sanity seeds (42) are fixed and logged; metrics, per-fold CSVs, and sanity results are written to `results/`. Re-running reproduced the reported numbers exactly (LR AUC 0.7360, GB 0.7267).

**Claims discipline — strong.** The report claims "no detectable difference" (gap −0.0092 within pooled SD 0.0134), backed by 15 folds with reported variance. It explicitly flags that this is a variance estimate, not a formal test, and recommends Wilcoxon/permutation for p-values. Limitations are honest (no tuning, synthetic data, no feature engineering). No claim exceeds what the code measured; the sanity table matches actual run output.

**Executability — excellent.** `pytest` → 19 passed in ~1.5s; `python3 run_experiment.py` completes in ~5s and regenerates results + REPORT.md.

**Code quality — good.** Clean module separation (data/evaluate/sanity/report), readable, declared deps all used. Minor nit: `import numpy as np` is unused in both `src/data.py` and `src/evaluate.py`.
