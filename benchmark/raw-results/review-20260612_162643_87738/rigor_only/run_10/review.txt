## Review: Churn Prediction — GradientBoosting vs LogisticRegression

**Inventory.** Clean, modular layout: `make_dataset.py` (generator with documented traps), `src/pipeline.py` (load/clean, feature engineering, pipeline factories), `src/evaluate.py` (CV + summarize), `run_experiment.py` (entrypoint with sanity checks + report writer), two test modules, `requirements.txt`, `results/metrics.json`, `REPORT.md`.

**Executability.** `pytest` → 22 passed in 2.3s. `python run_experiment.py` → completes in ~2.2s, regenerates data if absent, and reproduces `metrics.json` values exactly (LR 0.7328±0.0223, GB 0.6734±0.0284). Both declared commands work from a clean state.

**Leakage (strong).** The three planted traps are all caught:
- `account_status` (derived from target) is in `LEAKAGE_COLS` and dropped in `make_features`; a test asserts its absence.
- 200 exact duplicates removed via `drop_duplicates()` *before* the split, so they cannot straddle train/test.
- `signup_date` handled deliberately with `TimeSeriesSplit` on date-sorted data, with an explicit justification.
- `StandardScaler` lives inside the `Pipeline`, cloned per fold and fit on train only.

Two minor caveats: `signup_age_days` uses a global `min_date` computed over the full frame — harmless here because the data is sorted by date and TimeSeriesSplit always keeps the earliest rows in train, but it's a fit-on-all-data pattern. And the label-shuffle sanity check returns **AUC 0.628**, which the report itself flags `WARN — possible remaining leakage`; this residual signal (likely temporal feature drift) is reported honestly but never chased down.

**Methodology (solid).** Trivial baseline present (`DummyClassifier(stratified)` → 0.521). ROC-AUC is the appropriate primary metric for a 27% positive rate; F1 and accuracy also recorded. Tuning budget is equal — both use library defaults, explicitly documented. The growing TimeSeriesSplit train sizes confound the comparison somewhat, but this is acknowledged.

**Reproducibility (strong).** Seeds fixed throughout (model `random_state=42`, generator seed, shuffle seed 99). Config + metrics + methodology written to `results/metrics.json`. Re-run reproduces committed numbers exactly.

**Claims (weakest area).** The intervals genuinely do not overlap (LR lower bound 0.7105 > GB upper bound 0.7018), so the code's "LogisticRegression outperforms" headline follows its own logic. But there's an internal contradiction: limitation #3 reads "The null result should be interpreted as 'no strong evidence either way'" — clearly templated text that was *not* reconciled with this run, which declares a winner. Declaring a winner from 5 non-independent folds on a ±1-std-overlap heuristic (no formal paired test) is mildly overclaimed, though the report does hedge. The shuffle WARN is also not addressed in the conclusion.

**Code quality (good).** Readable, documented, well-factored, tests are meaningful. Minor blemishes: `import numpy as np` in `run_experiment.py` is unused; `accuracy` is computed/stored but never surfaced in the report.
