## Review

**Leakage (excellent).** All three planted traps are defused:
- `account_status` — confirmed it perfectly determines the target (closed ⟺ churned=1). Dropped in `src/data.py:21`. ✓
- 200 exact duplicates — removed via `drop_duplicates()` at `src/data.py:15` *before* the split, so they cannot straddle train/test. ✓
- `signup_date` — converted to `days_since_start`, rows sorted, and a genuine time-based split is used both for the hold-out (`temporal_split`) and the CV (`TimeSeriesSplit`). ✓

`StandardScaler` lives inside the `Pipeline`, so it is fitted train-only per fold in CV and on `X_train` only for the hold-out — no fit-transform leakage. `customer_id` dropped. One nit: `days_since_start` uses a global `min_date` computed before the split, but it's a monotonic constant offset and the global min coincides with the train min under a temporal split, so there's no practical leak.

**Methodology (good, one gap).** Metrics are appropriate for the 27% imbalance — ROC-AUC primary plus F1/precision/recall, never accuracy alone. Tuning budget is equal (zero/defaults) for both models and that's disclosed. The one real gap the rubric flags: **no trivial baseline** (no `DummyClassifier`/majority-class reference); LR serves as a de-facto simple baseline but a true null model is absent.
