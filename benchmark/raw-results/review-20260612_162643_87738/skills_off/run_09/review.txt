## Review

**Summary.** This is a strong, rigorous experiment. All four planted leakage traps are correctly handled, the code runs cleanly from a clean state, tests pass, and results reproduce bit-for-bit. The main weaknesses are statistical: the "winner" determination rests on a crude noise heuristic over non-independent folds, and the margin is razor-thin.

**Leakage (excellent).** All four traps caught:
- `account_status` is dropped via an explicit `LEAK_COLS` list, with a docstring explaining it encodes the target perfectly. Covered by a dedicated test (`test_account_status_absent`).
- The 200 exact duplicates are removed with `drop_duplicates()` *before* splitting (verified: 200 dropped, 4000 remain), so they cannot straddle folds.
- `StandardScaler` lives inside the LR `Pipeline`, so it is fit on the train fold only each CV iteration. GB correctly omits the scaler.
- `signup_date` is handled deliberately: rows sorted chronologically + `TimeSeriesSplit`, with a test asserting `train_idx.max() < test_idx.min()`.
- Minor nit: `reference_date` for `signup_days` is the global `min` over the whole dataset, computed before splitting — technically a train/test boundary crossing, but since the data is sorted ascending the global min always sits in fold-0's training set, so there is no actual leak.

**Methodology (good, not airtight).** Trivial baseline present (DummyClassifier → AUC 0.5) plus a label-shuffle check. Metrics are appropriate for the ~27% churn imbalance (ROC-AUC primary + avg_precision/F1/precision/recall; no reliance on accuracy). Equal tuning budget (both at defaults, acknowledged). The weak point: `determine_winner` defines "noise" as the *sum of the two fold-stds*, not a paired significance test. With `TimeSeriesSplit`'s expanding, overlapping training windows the folds are not independent, so those stds understate true variance — and the gap (0.0594) clears the noise band (0.0566) by only **0.0028**. The substantive conclusion (LR wins on a linearly-generated target) is almost certainly right, but the statistical justification is thin.

**Reproducibility (excellent).** Seed defaults to 42, threaded into both pipelines and logged in `results/metrics.json` config. Re-running the entrypoint produced byte-identical metrics. Config + per-fold CSV + JSON all written to `results/`.

**Claims (good).** REPORT.md reports mean±std with n=5 for every metric, lists honest and relevant limitations (single dataset, no tuning, signup_days distribution-shift risk, expanding window favoring complex models, fixed 0.5 threshold). Nothing claimed that the code didn't measure. Slight overconfidence in the bold "Winner: LogisticRegression" given how borderline the margin is.

**Executability (excellent).** `pytest` → 18 passed in ~2s. `python3 run_experiment.py` completes in seconds and reproduces. Dataset committed; regeneration documented.

**Code quality (good).** Clean modular split (`data`/`models`/`evaluate`), docstrings, declared+used deps. Minor smells: blanket `warnings.filterwarnings("ignore")` hides potential signals, and `summarise` computes mean/std over non-metric keys (`fold`, `train_size`) too — harmless but sloppy.
