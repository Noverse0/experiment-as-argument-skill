## Review: Churn Prediction Experiment

**What the experiment does:** Compares `LogisticRegression` vs `GradientBoostingClassifier` on a synthetic churn dataset, asking whether GB outperforms LR. I read all source, ran the tests, ran the entrypoint, and verified reproducibility.

### Leakage prevention — strong
All three planted traps were caught:
- **`account_status` dropped** (`pipeline.py:6,27`) — explicitly identified as a perfect target leak and removed before any modeling. ✓
- **Duplicates removed before splitting** (`pipeline.py:23`) — `drop_duplicates()` runs in `load_and_clean`, before `time_split`, so the 200 baked-in dupes can't straddle. Confirmed in output: "4200 rows, 200 duplicates removed." ✓
- **Temporal split, deliberately justified** (`pipeline.py:41-54`) — sorts by `signup_date`, earliest 70% train / latest 30% test, with an explicit rationale rejecting random splits. ✓
- **Scaler fit on train only** (`experiment.py:72-74`) — `fit_transform` on train, `transform` on test. ✓
- **Label-shuffle probe** (`experiment.py:81-87`) confirms AUC collapses to 0.44 (near chance) — a genuine leakage sentinel, not decoration.

Minor: `time_split` does a hard index cut after sorting; rows sharing the boundary `signup_date` could in principle straddle the split (the test only asserts `max_train_date <= min_test_date`, allowing equality). Day-resolution dates make this a soft, low-severity concern.

### Methodology — solid with disclosed gaps
- Trivial **majority-class baseline** present (AUC 0.5). ✓
- Metrics appropriate for ~27% imbalance: **ROC-AUC + Average Precision**, not accuracy. ✓
- **Tuning budget equal at zero** — both use defaults, honestly flagged. However GB gets a non-default `subsample=0.8` (`experiment.py:97`) specifically to manufacture seed variance; disclosed, but slightly asymmetric.
- **LR is deterministic** (lbfgs), so its 5 seeds yield std=0 — effectively n=1. The "5 seeds" framing over-states LR's variance evidence, though the report acknowledges the near-zero std.
- No statistical test, single temporal split — both disclosed as limitations.

### Reproducibility — excellent
- Seeds `[0,1,2,3,4]` fixed and logged in `metrics.json`. ✓
- Config + metrics written to `results/`. ✓
- **Verified:** re-running the entrypoint produced byte-identical metrics; `make_dataset.py` regenerates `churn.csv` deterministically (seed 7).

### Claims discipline — good, mildly overconfident
The report declares "**Logistic Regression appears stronger**" by 0.0216 AUC. The decision logic (`report.py:27`) only suppresses a winner if gap < 0.01 *or* spreads overlap — but LR's spread is artificially zero (deterministic), so the "no overlap" that licenses the winner claim rests on fake-zero variance rather than a real difference test. Language is appropriately hedged ("appears"), and the limitations section is genuinely honest (single split, synthetic data favoring the logistic process, need for paired tests). The "GB may be overfitting the training set" line is speculation the code never measured (no train-set scores reported).

### Executability — verified
`pytest` → 14 passed. `python run_experiment.py` runs clean and regenerates report + metrics. Dependencies declared in `requirements.txt` and all used.

### Code quality — clean
Well-factored (pipeline / experiment / report), good docstrings, tests cover dedup, leakage, temporal split, scaler discipline, and sanity checks. One dead import: `import sys` in `run_experiment.py:4` is unused.
