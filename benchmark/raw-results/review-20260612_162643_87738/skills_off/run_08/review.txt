## Review

**Leakage prevention — strong.** The headline trap is neutralized: `account_status` (which is `"closed"` iff `churned==1`) is explicitly dropped (`src/data.py:11,28`). The `StandardScaler` lives inside a `Pipeline` and is re-fit per fold on training data only (`src/models.py:9-12`, `src/evaluate.py:17`), so no test-fold statistics leak. The 200 planted exact duplicates are removed *before* any split (`src/data.py:23`), preventing train/test straddling. The temporal column is handled deliberately: `signup_date → days_since_first`, sorted ascending, evaluated with `TimeSeriesSplit` (`src/data.py:31-36`, `src/evaluate.py:10`). One minor nuance: the `min_date` reference for `days_since_first` is computed over the full dataset before splitting — negligible here since the earliest date sits in the first train fold anyway.

**Methodology — good.** Two trivial baselines are present (majority-class AUC=0.5 and a label-shuffle control that correctly falls to 0.525, gating the run). ROC-AUC is the primary metric with F1 reported alongside — appropriate for the 27% churn imbalance. Both arms use library defaults with equal (zero) tuning budget. The weak spot: the "winner if ±1 SD bands don't overlap" rule is a heuristic, not a proper paired/corrected significance test — fragile at n=5 folds, though they disclose it.

**Reproducibility — excellent.** Seeds are fixed and logged (model `random_state=42`, dataset `seed=7`, shuffle seed). Full config + metrics are persisted to `results/metrics.json`. I reran from a clean state (deleted data + regenerated) and got byte-identical data and exactly matching metrics.

**Claims discipline — good.** The report claims LR beats GB (gap −0.058, non-overlapping bands) and backs it with the 5-fold numbers. Limitations are honest and specific (5 folds noisy, no tuning, single synthetic draw, temporal-proxy caveat). No claim exceeds what the code measured.

**Executability — excellent.** `pytest` (13 passed) and `python run_experiment.py` both work from clean state; data auto-generates if absent.

**Code quality — strong.** Clean module separation (data/models/evaluate), no dead code, all four declared dependencies used.
