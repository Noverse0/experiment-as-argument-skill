## Summary

This is a strong, rigorous experiment that **avoids all three planted traps**:

- **`account_status` (the perfect leak)** is explicitly dropped in `src/pipeline.py:38` and confirmed absent by a dedicated test.
- **Duplicate rows** are removed *before* any split (`load_and_clean`, `pipeline.py:20`), so the 200 dups can't straddle train/test.
- **The temporal column** is handled deliberately via `TimeSeriesSplit` on date-sorted data — training always precedes test in time.

Fit-like transforms are clean too: `StandardScaler` lives *inside* the `Pipeline` and is cloned+fit per fold on train only (`experiment.py:59-62`), so no scaler leakage.

Weaknesses are in the claim/methodology layer rather than leakage:

1. **Verdict by ad-hoc heuristic, not a statistical test.** The "winner" is decided by `abs(gap) < max(fold_std)` (`run_experiment.py:87`). The gap (0.058) clears that bar, but there's no paired test across folds and only a single data seed — so the headline "Logistic regression outperforms gradient boosting" is stronger than the evidence licenses. The limitations section does honestly flag the single seed and that the logistic DGP structurally favors LR.
2. **Report contradicts its own code on the baseline.** REPORT.md says the majority baseline ROC-AUC is "N/A" and "cannot be computed (no probability output)", but `metrics.json` and the run output both show 0.500 — the code *did* compute it.
3. **Seed conflation / incomplete logging.** The dataset is generated with seed 7 (`make_dataset.py` default), but the report claims "same random seed (42)". The data-generation seed is not recorded in `results/metrics.json`, so reproducibility of the *data* relies on an undocumented default.
4. Minor: `days_since_ref` is a pure-noise feature in the DGP, and with `TimeSeriesSplit` the test fold's dates always exceed the training range (extrapolation) — harmless here but worth noting.
